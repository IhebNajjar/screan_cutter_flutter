## 1. Executive Summary & Evolution

In **Workshop 3 (TP3)**, the waiting room application implemented reactive local state using `Provider` and `ChangeNotifier`. While decoupled and responsive within a single application instance, state lived strictly in device memory—disappearing when the app was closed and unable to synchronize with other users or screens.

In **Workshop 4 (TP4)**, the architecture underwent a full transformation into a **distributed, cloud-backed real-time system**:
* **Backend as a Service (BaaS)**: Supabase PostgreSQL provides permanent cloud persistence.
* **WebSocket Realtime Subscriptions**: Changes (`INSERT`, `DELETE`) are broadcast in milliseconds to all connected devices without manual polling.
* **Row Level Security (RLS)**: Enforces access control directly in PostgreSQL, securing table access while permitting anonymous queue operations.
* **Resilient Data Parsing**: Hardened parsing logic supporting null-safety and dynamic column mapping.

## 3. Deep Function & Class Breakdown

### A. Data Model ([`lib/models/client.dart`](file:///c:/Users/ihebn/OneDrive/Documents/dsi31/crospllatform/waiting_room_app/lib/models/client.dart))

Encapsulates queue tickets with type-safe properties, serialization, and defensive parsing:

#### 1. `Client` Class Properties
* `final String id`: Unique identifier (UUID generated by PostgreSQL `gen_random_uuid()`).
* `final String name`: Name of the client in the waiting line.
* `final DateTime createdAt`: Timestamp recording when the client joined the queue, maintaining strict First-In-First-Out (FIFO) ordering.

#### 2. `Client({required this.id, required this.name, required this.createdAt})`
* Standard immutable constructor requiring all three core fields.

#### 3. `factory Client.fromMap(Map<String, dynamic> map)`
* **Purpose**: Converts incoming database JSON/Map payloads into strongly typed `Client` objects.
* **Resilience Features**:
  - Safely extracts `created_at` with fallback to `map['crea']`.
  - Protects against `null` values by falling back to `DateTime.now()`.
  - Safely casts `id` and `name` to `String`, preventing `type 'Null' is not a subtype of type 'String'` crashes.

#### 4. `Map<String, dynamic> toMap()`
* **Purpose**: Serializes a `Client` instance back into a JSON-compatible map for database writes or testing.
* **Fields**: Serializes `id`, `name`, and `created_at` (formatted as ISO-8601 string).

#### 5. `String toString()`
* Returns human-readable string representation: `'Client(id: $id, name: $name, created_at: $createdAt)'`.

#### 6. `operator ==(Object other)` & `int get hashCode`
* Implements value equality based on `id` and `name` to allow accurate test assertions and list comparisons.

### B. State Provider ([`lib/queue_provider.dart`](file:///c:/Users/ihebn/OneDrive/Documents/dsi31/crospllatform/waiting_room_app/lib/queue_provider.dart))

Inherits from `ChangeNotifier` to manage business logic, network synchronization, and reactive UI updates:

#### 1. `List<Client> get clients`
* Exposes `List.unmodifiable(_clients)` to protect internal state from direct external mutation while allowing read access for UI widgets.

#### 2. `QueueProvider({SupabaseClient? client})`
* **Constructor**: Initializes the provider with an optional Supabase client (defaulting to `_getSupabaseClientSafely()`).
* Automatically calls `_fetchInitialClients()` and `_setupRealtimeSubscription()` on startup.

#### 3. `QueueProvider.forTesting(SupabaseClient supabase)`
* Specialized constructor annotated with `@visibleForTesting` allowing unit tests to inject a mock Supabase client without touching production networks.

#### 4. `static SupabaseClient? _getSupabaseClientSafely()`
* Helper method returning `Supabase.instance.client` if initialized, or `null` if running offline or in unit tests, preventing crash on uninitialized access.

#### 5. `Future<void> _fetchInitialClients()`
* **Purpose**: Performs the initial read query to populate the queue on app launch.
* **Behavior**:
  - Queries `_supabase.from('clients').select().order('created_at', ascending: true)`.
  - Maps returned rows through `Client.fromMap`.
  - Clears local list, inserts fetched clients, sorts by `createdAt`, and triggers `notifyListeners()`.
  - Includes defensive fallback if the `created_at` ordering column differs.

#### 6. `void _setupRealtimeSubscription()`
* **Purpose**: Establishes a persistent WebSocket connection listening for PostgreSQL database events.
* **Behavior**:
  - Connects to channel: `_supabase.channel('public:clients')`.
  - Listens to `PostgresChangeEvent.all`.
  - **On `insert`**: Deserializes `payload.newRecord`, removes duplicate IDs, inserts the new client, sorts the queue by `createdAt`, and calls `notifyListeners()`.
  - **On `delete`**: Extracts `payload.oldRecord['id']`, removes the client from `_clients`, and calls `notifyListeners()`.
  - Calls `.subscribe()` once.

#### 7. `Future<void> addClient(String name)`
* **Purpose**: Adds a new client to the waiting queue.
* **Behavior**:
  - Trims whitespace and validates that the name is not empty.
  - Inserts row `{'name': trimmedName}` into the Supabase `clients` table.
  - Supabase auto-generates the `id` (UUID) and `created_at` timestamp.
  - Automatically notifies all connected devices through Realtime.

#### 8. `Future<void> removeClient(String id)`
* **Purpose**: Deletes a specific client ticket by ID.
* **Behavior**:
  - Issues `_supabase.from('clients').delete().eq('id', id)`.
  - Supabase deletes the record and broadcasts the deletion event.

#### 9. `Future<void> nextClient()`
* **Purpose**: Implements FIFO (First-In, First-Out) queue processing.
* **Behavior**:
  - Validates that `_clients` is not empty.
  - Retrieves the earliest client in line (`_clients.first`).
  - Calls `removeClient(firstClient.id)` to dequeue the ticket.

#### 10. `@override void dispose()`
* Closes active WebSocket channel subscriptions (`_channel?.unsubscribe()`) to prevent memory leaks when the widget tree unmounts.

### C. Application Entry & UI ([`lib/main.dart`](file:///c:/Users/ihebn/OneDrive/Documents/dsi31/crospllatform/waiting_room_app/lib/main.dart))

#### 1. `void main() async`
* Calls `WidgetsFlutterBinding.ensureInitialized()`.
* Loads environment variables from `.env` using `dotenv.load(fileName: ".env")`.
* Reads `SUPABASE_URL` and `SUPABASE_ANON_KEY`.
* Initializes Supabase client: `await Supabase.initialize(url: ..., anonKey: ...)`.
* Mounts the application wrapped in `ChangeNotifierProvider(create: (_) => QueueProvider(), child: const WaitingRoomApp())`.

#### 2. `WaitingRoomApp` (StatelessWidget)
* Configures top-level `MaterialApp`, theme styling (`ColorScheme.fromSeed(seedColor: Colors.blue)`), disables debug banner, and sets `WaitingRoomScreen` as home.

#### 3. `WaitingRoomScreen` (StatefulWidget) & `_WaitingRoomScreenState`
* Manages the text editing controller `_controller`.
* **`_submitClient()`**: Reads `_controller.text`, dispatches `context.read<QueueProvider>().addClient(name)`, and clears the input field.
* **`build(BuildContext context)` Layout Tree**:
  - **`AppBar`**: Displays title `"Waiting Room"` centered.
  - **Input Row**: `TextField` with `"Enter name"` placeholder + `ElevatedButton` titled `"Add"`.
  - **Queue List (`Consumer<QueueProvider>`)**:
    - If empty: Renders placeholder `"No one in queue yet..."`.
    - If populated: Renders `ListView.builder` displaying a `Card` for each client with their name, formatted timestamp, and a red delete `IconButton`.
  - **Next Client Button**: Prominent green `ElevatedButton.icon` with arrow icon calling `context.read<QueueProvider>().nextClient()`.

## 4. User Guide: How to Use the App

### Step 1: Launch the Application
Open a terminal inside the project directory:
```powershell
cd waiting_room_app
flutter run -d chrome
```
*(Or run on Edge: `flutter run -d edge`, or Android Emulator: `flutter run -d android`)*

### Step 2: Add a Client to the Queue
1. Type a name (e.g., `"Alice"`) in the text box.
2. Click **Add** or press Enter.
3. The client is immediately saved to the Supabase cloud database and appears in the list with a creation date.

### Step 3: Real-Time Multi-Device Sync
1. Open the app on two devices or two separate browser windows simultaneously.
2. When you add a client on Window 1, **it appears on Window 2 instantly with zero refresh**.

### Step 4: Dequeue / Call the Next Client
1. Click the green **Next Client** button at the bottom of the screen.
2. The earliest client in line is dequeued from both the database and all connected screens simultaneously.

### Step 5: Remove a Specific Client
* Tap the **red trash can icon** on any individual card to remove that specific client immediately.

## 5. Supabase Cloud Configuration & Row Level Security (RLS)

### Database Schema
```sql
CREATE TABLE IF NOT EXISTS public.clients (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### Row Level Security (RLS) Policies
PostgreSQL RLS ensures that unauthorized access is blocked while allowing our Flutter clients using the `anon` key to read, add, and dequeue tickets:
```sql
-- 1. Allow reading queue
CREATE POLICY "Allow public select" 
ON public.clients FOR SELECT TO anon 
USING (true);

-- 2. Allow adding tickets
CREATE POLICY "Allow public insert" 
ON public.clients FOR INSERT TO anon 
WITH CHECK (true);

-- 3. Allow dequeuing tickets
CREATE POLICY "Allow public delete" 
ON public.clients FOR DELETE TO anon 
USING (true);
```

### Realtime Publication
```sql
ALTER PUBLICATION supabase_realtime ADD TABLE public.clients;
```
